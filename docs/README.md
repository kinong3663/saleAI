# 文档索引

> 这个目录是项目的**设计与决策档案**。开发时不用全看，按下面的索引取用即可。

---

## 权威层级

文档之间出现矛盾时，**按这个顺序裁决**（越靠上越权威）：

```text
1. 决策记录.md           所有决定的最终结论，冲突时以它为准
2. 实施文档.md           代码契约与施工顺序
3. 数据表构建与说明.md    表结构与字段约定
4. 技术栈构建与说明.md    工程约定与边界
5. 答辩准备.md           只在交付与答辩阶段使用
```

---

## 每份文档管什么

| 文档 | 回答什么问题 | 什么时候看 |
|---|---|---|
| **决策记录.md** | 每个决定是什么、为什么、可逆成本多高 | 犹豫时、写 README 时、答辩前 |
| **实施文档.md** | 代码长什么样、按什么顺序写、怎么算做完 | 开发全程 |
| **数据表构建与说明.md** | 表怎么来的、字段怎么定、索引给谁用 | 写任何数据库代码前 |
| **技术栈构建与说明.md** | 用什么技术、代码放哪、哪些坑不能踩 | 搭骨架时、写新模块时 |
| **答辩准备.md** | README 怎么写、答辩怎么答、现场题怎么接 | 交付前、答辩前 |

---

## 推荐阅读顺序

**第一次上手（约 40 分钟）**

```text
1. 决策记录.md 第 1 节        决策总表，一页看完所有结论
2. 数据表构建与说明.md 第 4 节  Prisma schema，系统的骨架
3. 技术栈构建与说明.md 第 5 节  架构分层与三条铁律
4. 实施文档.md Part 2          施工段与验收标准
```

第 1、4 节的 `基础部分设计与实现框架.md` 已经归档，不需要读。

**开发中的查阅路径**

```text
要写新模块        → 技术栈文档第 5、9 节（边界与编码约定）
要动数据库        → 数据表文档第 4、6、7 节
不知道下一步做什么 → 实施文档 Part 2 的依赖关系图
某段怎么做算完成   → 实施文档里该段的「验收标准」
该不该加某个功能   → 决策记录第 4 节（不做清单）+ 第 5 节（可逆成本）
```

**交付前的查阅路径**

```text
README 怎么写     → 答辩准备.md 第 2 节
AI_NOTES 怎么写   → 答辩准备.md 第 3 节
答辩怎么答        → 答辩准备.md 第 4、5 节
现场题怎么接      → 答辩准备.md 第 6 节
Demo 怎么走       → 决策记录.md 的 Q8
```

## 文档之间的关系

```text
决策记录.md ──────┬──► 实施文档.md ──► 代码
（为什么这么定）   │     （代码长什么样）
                  ├──► 数据表构建与说明.md ──► schema
                  ├──► 技术栈构建与说明.md ──► 工程约定
                  └──► 答辩准备.md ──► README / 答辩
```

**决策记录是根**，其余四份文档都是它的展开。所以改动任何一个决定时，要顺着这个图检查哪些下游文档需要同步更新。
